## 一、这是什么

任务列表（左侧队列）里把若干任务收在一个**可折叠的表头**下：

```
   ... 拉黑订单好友
   ▾ 周常                    ← 表头：只有折叠箭头 + 组名
      ☐ 创生微粒刷取   ⚙     ← 与普通任务完全同级
      ☐ 周本         ⚙
   ... 基建
```

**行为约定**：

| 操作 | 行为 |
|---|---|
| 点表头 | 折叠 / 展开 |
| 折叠 | 组内**全部**任务隐藏，只剩表头一行 |
| 展开 | 组内任务全部显示，各自独立勾选 |
| 拖表头 | **整组上下移动，组内顺序不变** |
| 表头本身 | **没有任何功能**（不勾选、不执行、不进配置）|
| 组内任务 | 与普通任务**完全同级**：独立勾选、独立执行、按队列顺序跑 |

## 二、数据层：用官方 `group` 字段，零 schema 改动

`interface.json` 顶层声明分组，任务声明归属：

```json
{
    "group": [
        { "name": "周常", "label": "周常", "description": "...", "default_expand": true }
    ],
    "task": [
        { "name": "创生微粒刷取", "entry": "创生微粒刷取", "group": ["周常"] },
        { "name": "周本",         "entry": "周本",         "group": ["周常"] }
    ]
}
```

### 为什么不用 MFA 现成的分组渲染

MFA **有** `group` 机制，但只被 `AddTaskDialogViewModel.BuildGroups` 使用 —— 也就是**点「+」添加任务时的对话框**。任务列表（`TaskQueueView.axaml`）里 `GroupNames` / `IsExpanded` / `Expander` / `TreeView` **全为 0**，完全没有分组。

### 为什么不能加自定义字段

`interface.schema.json` 里 option 与 taskItem 的所有分支都是 `additionalProperties: false`，加自定义的"子任务/可见性"字段会被 `validate_schema.py` 拦下，而 schema 是上游同步的不能改。

**所以：复用 `group`（schema 合法）承载父子关系，UI 自己实现折叠。**

## 三、核心设计：表头画在「组内第一行」上，不注入任何行

### 为什么不往集合里插一个表头行

MFA 已有的先例是 `IsResourceOptionItem` —— 把"非任务行"放进同一个 `TaskItemViewModels` 集合，各处逻辑按这个标记过滤。**但 `IsResourceOptionItem` 有 66 处引用、横跨 12 个文件**（含配置保存路径）。新增一种行类型就得把这 66 处全部改成"也排除表头"，**漏一处就可能把 `null` 存进配置**。

### 实际做法

```
表头不占用独立行，而是画在「组内第一行」的顶部；
折叠时把该行的任务内容一起隐藏 —— 视觉上就等同于只剩一个表头。
```

**收益**：`TaskItemViewModels` 的构成**完全没变**，66 处过滤逻辑一行都不用动，配置保存/执行/勾选/拖拽全部不受影响。

**代价**：折叠时那一行在技术上仍是组内第一个任务（悬停/选中会作用于它），但视觉上与纯表头无异。

### 折叠时的三层隐藏

| 层 | 绑定的标记 | 作用 |
|---|---|---|
| `ListBoxItem` 容器 | `!IsHiddenByGroup`（代码里设，见§五）| 非表头成员**整行**隐藏（连容器一起）|
| 模板内 `Border` | `HasGroupHeader` | 只有载体显示表头 |
| 模板内 `Panel` | `!IsTaskContentHidden` | 折叠时载体也只留表头 |

**只藏模板内容是不够的** —— `ListBoxItem` 容器仍在，主题的 Padding 会撑出一个可 hover 的空行。必须连容器一起隐藏。

## 四、状态字段（`DragItemViewModel`）

```csharp
[ObservableProperty] [JsonIgnore] private string? _groupKey;            // 所属组名
[ObservableProperty] [JsonIgnore] private string? _groupLabel;          // 表头显示文字（仅载体非空）
[ObservableProperty] [JsonIgnore] private bool   _hasGroupHeader;       // 本行是否画表头
[ObservableProperty] [JsonIgnore] private bool   _isGroupExpanded;      // 箭头方向
[ObservableProperty] [JsonIgnore] private bool   _isHiddenByGroup;      // 整行隐藏（非载体成员）
[ObservableProperty] [JsonIgnore] private bool   _isTaskContentHidden;  // 只藏任务内容（含载体）
```

`IsHiddenByGroup` 与 `IsTaskContentHidden` **必须分开**：折叠时载体的这两者取值相反（要保留表头、只藏内容），一个标记表达不了。

## 五、核心流程（`TaskQueueViewModel`）

### 5.1 监听挂载（**关键，挂错地方整个功能静默失效**）

```csharp
// 必须在 Initialize()（加载任务）之前挂上
TaskItemViewModels.CollectionChanged += OnTaskItemsCollectionChanged;
Initialize();
```

**不能挂在 `OnTaskItemViewModelsChanged`** —— 那是 `[ObservableProperty]` 的 setter 回调，只有集合被**整体重新赋值**时才触发；而 `TaskItemViewModels` 初始化为 `[]` 之后**全程原地 `Clear`/`Add`**，setter 永远不触发。

### 5.2 `RefreshTaskGroups()` —— 重算标记

按**当前队列顺序**扫描连续的同组片段：

- 只在**成员连续排列**时才成组；被拆散则该组退回普通显示
- 表头标记挂在**锚点**（见 5.4）上；锚点不在场时退回"当前第一个成员"
- 折叠时：非锚点成员 `IsHiddenByGroup = true`，所有成员 `IsTaskContentHidden = true`

### 5.3 `CoalesceOrder()` —— 算目标顺序（纯函数，不改集合）

```
整组只在「锚点」出现的位置输出；其余成员跳过，等锚点出现时一起输出。
输出顺序：锚点在前，其余成员按当前相对顺序跟随。
```

**锚点必须是"用户拖的那一个"**，不能用"当前排第一的成员"。

### 5.4 锚点来源：**直接从拖拽事件读**

```csharp
DragItemViewModel? moved = e.Action switch
{
    Move when e.NewStartingIndex 合法 => TaskItemViewModels[e.NewStartingIndex],
    Add                                => e.NewItems?.OfType<DragItemViewModel>().FirstOrDefault(),
    Replace                            => e.NewItems?.OfType<DragItemViewModel>().FirstOrDefault(),
    _ => null,
};
if (moved != null && TaskGroupKeyOf(moved) is { } key)
    _taskGroupHeaderCarrier[key] = moved;   // 谁被拖，谁就是该组锚点
```

两种拖拽实现都覆盖：`Move`（直接移动）和 `Remove+Insert`（`Add` 里带被移动的项）。

### 5.5 `ApplyGroupCoalesce()` —— 落地（延后一帧）

`Dispatcher.UIThread.Post(...)` 延后执行，避免在 `CollectionChanged` 处理中直接改集合；用 `Move()` 逐项搬到目标位置。`_refreshingTaskGroups` 做重入保护。

**「拖表头 = 整组移动」就是这么实现的**：表头画在锚点上 → 拖它 = 拖锚点 → 收拢时其余成员跟到锚点的新位置。

### 5.6 容器可见性：**唯一判定处**

```csharp
private static void ApplyGroupRowVisibility(ListBoxItem container)
{
    if (container.DataContext is not DragItemViewModel vm) { container.IsVisible = true; return; }
    container.IsVisible = vm.IsTaskSupported && !vm.IsHiddenByGroup;
}
```

必须在**三个时机**都调用：

1. `ContainerPrepared`（容器生成）
2. 该行 `IsHiddenByGroup` 变化（`PropertyChanged`）
3. **集合变化后全量重套**（`CollectionChanged` → `Dispatcher.Post`）—— 拖拽会回收复用 `ListBoxItem`，复用的容器前两者都不触发

## 六、踩过的坑（改这块之前务必读）

| # | 现象 | 真因 | 修法 |
|---|---|---|---|
| 1 | 界面完全看不到分组 | `RefreshTaskGroups()` 一次没跑 —— 监听挂在 `OnTaskItemViewModelsChanged`，而集合是原地增删，setter 从不触发 | 监听挪到**构造函数、`Initialize()` 之前**（§5.1）|
| 2 | 表头出来了，但组里只有 `周本` | 存档里 `group = None`：`TaskLoader.UpdateExistingItem()` 逐字段拷贝时**漏了 `Group`**；队列项复用的是存档里的旧对象 | 补上 `oldItem.InterfaceItem.Group = newItem.Group`；`TaskGroupKeyOf` 再加按 entry/name 回查顶层定义的兜底 |
| 3 | 两个成员被拆成两个单成员组 | 加载器多轮同步时把别的任务插到了两个成员中间（存档顺序是对的，内存顺序被改了） | 新增**自动收拢**（`CoalesceOrder`）|
| 4 | 折叠时首个任务仍显示 | `IsHiddenByGroup = !expanded && i > index` 对首成员永远 false，而表头正画在首成员上 | 拆出独立的 `IsTaskContentHidden`，内容面板改绑它 |
| 5 | 向下拖无效、向上拖正常 | 收拢锚点取的是"组内第一个成员"——向下拖时被拖的跑到后面，锚点落在**没被拖动的**那个成员上，整组被拉回 | 锚点改为**粘性载体**；再改为**从拖拽事件直接读**（§5.4）|
| 6 | 拖拽后多出一个空行，开合一次又消失 | ① 上游既有的 `UpdateTaskItemContainerVisibility()` **无条件** `container.IsVisible = item.IsTaskSupported`，把我隐藏的容器设回可见；② 容器复用导致可见性滞后 | 该既有方法改为调用 `ApplyGroupRowVisibility`（合并成唯一判定处）；并在集合变化后全量重套（§5.6）|
| 7 | 折叠后空行仍在 | 只隐藏模板内容不够，`ListBoxItem` 容器的 Padding 会撑出一行 | 容器级隐藏（§5.6）|
| 8 | 组内任务整行消失 | 我为治空行加的条件 `(!IsTaskContentHidden \|\| HasGroupHeader)` **依赖刷新时序** —— `UpdateTaskItemContainerVisibility` 在集合变化后被调用时标记可能还是旧的，会把正常行误判成空壳 | **去掉该条件**。真凶（第 6 条①）修掉后它已无必要 |

### 两条通用教训

1. **先搜同类副作用，再动自己的代码。** 第 5~7 轮我一直在新写的代码里找原因，而空行真正的成因是上游既有方法在覆盖我的设置 —— 一次 `grep IsVisible` 就能找到。
2. **只保留有证据支撑的改动。** 第 8 条那个条件是"顺手加的保险"，没有证据支撑，反而引入了新 bug。

## 八、如何新增一个分组

只改 `interface.json`，**不用碰代码**：

```json
"group": [
    { "name": "周常", "label": "周常", "default_expand": true },
    { "name": "月度", "label": "月度任务", "default_expand": false }   // 新增
],
"task": [
    { "name": "某月度任务", "entry": "xxx", "group": ["月度"] }
]
```

注意：

- 同组成员在 `task` 数组里**尽量相邻**（不相邻也能被自动收拢，但相邻更直观）
- 一个任务只取 `group[0]` 作为分组依据
- 组内成员会**连着执行**（收拢会改变队列顺序，执行顺序随之改变）
