# 交接：周本「碎星虚影」领奖流程

> 对应改动：`assets/resource/pipeline/base/周本.json`、`assets/interface.json`、`tools/test_weekly_reward.py`
> 起因：活动探索页的「本周报酬微晶」显示从**左下角**挪到了**碎星虚影卡片顶部**，且点卡片会弹奖励领取页、领完后卡片可能不在原位。

## 一、这件事要做什么（作者原话整理）

1. **新的正常流程**：点活动探索 → 进入活动探索页 → 在「应有位置」识别到碎星虚影 → 点一下卡片 → 弹出奖励领取页 → 点边缘回到活动探索页 → 周本任务就完成了。此时碎星虚影区域会挪到最右侧。
2. **容错 A（任务选项「领取完奖励就结束」）**：进入活动探索页后，如果**没有**在应有位置识别到碎星虚影，则任务默认**成功完成**并结束。
3. **选项 B（「领取完奖励依然进行挑战」）**：没在应有位置识别到时，在**卡片标题高度**（固定高度，不随文字变化）**向左滑**，重复直到识别到碎星虚影 → 读取当前报酬 → 继续挑战流程。
4. **回到活动探索页后卡片仍在原位** → 继续执行原有的正常挑战流程。

> - 「应有位置」= **从出击页初次进入活动探索页时的位置**（作者确认口径）。
> - 具体是卡片条**最左槽位**：**未领取/未领完**时碎星虚影就在最左；**领取完会挪到最右**（作者补充说明 + 2026-09-21 实测）。
> - ⚠️ 旧的 `活动探索_碎星虚影` roi `[450,443,302,98]`（x 450-752）盖的正是**最右**那档 —— 也就是说它匹配的是"已领完"的位置，做「应有位置」判定必须换 ROI（见 §二）。

> - ✅ **滑动方向：维持原本的「向左拖」**（begin 620 → end 120），2026-09-21 **11:08 日志实测**：
>   改成向右拖（120→620）后连滑 3 次都找不到卡片（把右侧内容推出去了）→ 已改回向左拖。
>   11:02 日志里「左拖之后卡片在 x≈786」是**进入页面时的滚动状态不同**造成的，不是拖拽方向的问题 —— 别重蹈这个误判。
> - ✅ **容错规则（作者 2026-09-21 定）**：**不去要求卡片先滑回「应有位置」——一旦识别到「碎星虚影」就点它的文本所在位置**
>   （`活动探索_碎星虚影` 用整条卡片带 ROI + Click，点 OCR 框中心，不指定 target）。
>   滑动只负责把卡片挪进可视区，找到即可；`周本_读取报酬` 读不到报酬时走 `on_error` 直接去点，不再把任务拖死。
> - ⚠️ **报酬框 ROI 要覆盖整条顶部带**（`[20,185,1240,100]`）：卡片可以跑到 x≈786，
>   报酬框随之到 x≈840+；窄到 x=780 时读不到 → `周本_读取报酬` 失败、任务死（日志实例）。
> - ⚠️ **领奖弹窗只在「未领取时点碎星虚影」这条路上出现**（作者 2026-09-21 声明）：
>   所以弹窗处理只挂在 `周本_点击碎星虚影_领奖` 之后，**不进入**「领奖后 / 继续挑战」链路，
>   也不会出现在关卡选择页 / BOSS 选择页的上下文里。测试 `test_reward_popup_only_on_unclaimed_path` 守这条约定。
> - 弹窗点击点用**原有的外侧位** `1280(1120,360)`（未领取时弹窗盖在活动探索页上，那个位置是空白）。
> - ⚠️ **卡片已经右移（= 已领完）时，找回并继续挑战这条路上完全不用考虑领奖**（作者 2026-09-21 补充声明）：
>   即「分派 → 右滑 → 找到 → 读取报酬 → 点击卡片 → BOSS 选择页」这条链上不许出现任何领奖节点。
>   测试 `test_moved_right_path_never_touches_claiming` 守这条约定。

|---|---|---|

| **600/600** | (578, 219, 110, 32) | 实测 |
| 6天17:38:03后重置 | (545, 259, 152, 18) | 实测 |
| 活动探索页标题 | (548, 78, 166, 40) | 实测 |
| 出击菜单里的「活动探索」入口 | (602, 137, 98, 28) | 实测 |

**卡片条槽位**（2026-09-21 实机截屏量的三个可见槽位标签 x，1280 基准；间距约 245）：

| 槽位 | 标签 x 范围 | 出现的卡片（当天） | 用途 |
|---|---|---|---|
| 槽 1 | 42 ~ 141 | 落日战线 | **「应有位置」= 这一档**（未领取时碎星虚影在这） |
| 槽 2 | 285 ~ 394 | 实战预演 | — |
| 槽 3 | 521 ~ 650 | 碎星虚影 | **已领完时碎星虚影挪到这**（旧 roi 盖的就是这里） |

因此「应有位置」的 ROI 取 `[20,445,265,95]`（覆盖槽 1，留余量，且不碰到槽 2 的 x≥285）；
`周本_碎星虚影_应有位置` 与 `周本_碎星虚影_原位置仍在` 都用它。

**结论**（2026-09-21 作者补充「未领取状态」截图后修正）：

- 新版 UI 里**报酬框恒在卡片顶部**，与领没领无关：未领取显示 `0/600`、领完显示 `600/600`。
  09-14 日志里左下角那个 `0/600` 属于**旧版 UI**，已作废。
- 报酬框的 **x 跟着卡片走**：作者补充的截图里碎星虚影在**最左**（旁边是永境战域 / 阀限禁区），
  而本次实测那一次它在**最右**。两个位置都要能读到 → ROI 覆盖**整条顶部带** `[20,185,1240,100]`
  （y 带按实测：本周报酬微晶 y=202、600/600 y=219、重置行 y=259）。
- 碎星虚影**标签**位置区分不了「未领完 / 已领完」（实测两者都在 x≈520），这一点仍然成立：
  「卡片在不在应有位置」是**流程分支**依据，不是"领没领"的依据。

**两个节点共用同一个 roi**：`活动探索_已存在`（原有流程）、`周本_读取报酬`（新流程）。

## 挑战次数（2026-09-21 补充）

- 仅选择「领取完奖励依然进行挑战」时显示「自定次数」下拉项，范围 1–10，默认 1。
- `周本_次数初始化` 在任务入口读取当前 MFA 实例的设置，Agent 只记录目标与已完成次数。
- 第三场战斗结算并回到 BOSS 选择页，重新识别到「虚影阿瑞斯」或「虚影宙斯」后，`周本_挑战完成_*` 才将次数加 1。未回到该页面不计数。
- `周本_次数分派` 在达到目标后返回主页，否则重新进入所选关卡。「依然进行挑战」会跳过旧 `600/600` 提前结束节点。
- `活动探索_碎星虚影` 的点击 OCR 扩为 `[20,443,850,98]`，同时覆盖最左与偏右槽位。
- 09:37 那次日志中的周本失败由自动资源更新强制停止任务引起，**没有证据表明它运行到了新界面识别节点**。按用户要求，更新与任务并发问题暂不处理。

## 七、踩过的坑（别重复）

- **已进入 BOSS 选择页时不要盲点领奖**：2026-09-21 日志中，领奖节点的旧固定点击 `(1120,360)` 落在尼克罗卡片上；随后 OCR 才读到戈里刻。点击碎星卡片后现在先判 BOSS 选择页，命中后只点击「戈里刻虚影」的 OCR 文字框；领奖点击也移到了卡片上方。修改管线后须重启 MFA，否则 MaaFW 继续使用已加载的旧节点。
- **卡片条在最右端时左右拖都不动**：别把它当「滑动没生效」——那正是没有可翻内容的状态。
- **报酬框有两个位置**：旧位左下角 `[86,623,152,40]` 已作废，`活动探索_已存在` 与 `周本_读取报酬` 两处都要用新位，否则一个读得到、一个读不到。
- **`ocr_screenshot.py` 的坐标列**：认「1920基准」那列（见 §二 的坑）。
- **改 `interface.json` 必须重启 MFA**，否则新选项不出现。
- 抽卡片/下拉这类**位置敏感**的识别，不要只写单个模式：`expected` 是数组、任一命中即可（正则子串），本仓既有写法见 `主线刷取_点击虚拟场域_第一次`。
